## Contribution rules

1. Keep content public-safe and generic.
2. Do not add secrets, private infrastructure identifiers, private runtime paths, or private operational state.
3. Preserve the narrow Yellow-Control scope: authority, ADAL, CDEL, ESAL, PCL, gates, backup/rollback, external access, secrets, GitHub governance, telemetry, and skill behavior.
4. Keep `skills/yellow-control-governance/SKILL.md` concise and Hermes-compatible.
5. Prefer small, reviewable pull requests.

## Validation checklist

- Frontmatter parses for the skill.
- Markdown tables start at column 1.
- Mermaid fences, if introduced, start at column 1.
- No forbidden strings, secrets, or private operational data are present.
- Documentation and skill behavior remain aligned.
