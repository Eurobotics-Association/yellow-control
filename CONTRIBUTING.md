## Contribution rules

1. Keep content public-safe and generic.
2. Do not add secrets, real credentials, private hostnames, private IPs, or private internal repo coordinates.
3. Keep governance examples non-destructive and dry-run friendly.
4. Preserve Hermes skill compatibility (`SKILL.md` + valid YAML frontmatter).
5. Prefer small, reviewable pull requests.

## Validation checklist

- Frontmatter parses for every skill.
- No forbidden strings (private markers, secrets patterns, private hostnames/IPs).
- Example scripts pass shell syntax checks.
- Documentation and skill behavior remain aligned.
